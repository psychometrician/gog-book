21  Edge

Which things in your table are connected to which? edge draws one stroke per row of the table, between the two things named in that row. Every other mark that draws a stroke is placed by its values on the axes. A line and a path join points at their x and y values, and an interval spans two values on one axis. An edge is different: each row gives it only two names, and no column says where a name is placed on the page. A plot of edges is a network diagram.

So an edge takes no x, y or z. It is the only mark that takes none of the three. An edge’s endpoints come from a layout, a transform that reads the two columns of names and places each distinct name once. Write the from column first and the to column second, so the sentence states the direction of each relation. If you swap the two columns, the picture does not change. It changes only when you add arrowheads: style(arrow = "end") points each edge from the first column to the second (What you can set).

21.1 The network diagram

A network diagram needs a table with one row per relation. In trade_partners, each row names an exporter and an importer, gives the value of the goods in rounded billions of dollars, and names the exporter’s continent:

trade_partners: first 5 of 22 rows
exporter importer billions continent
China United States 500 Asia
Mexico United States 455 Americas
Canada United States 420 Americas
United States Mexico 320 Americas
United States Canada 355 Americas

Name the table, then write three things: the mark, the layout that derives it, and the space network():

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) + edge * layout(exporter, importer) + network()
data(trade_partners) + edge * layout(col.exporter, col.importer) + network()
data(trade_partners) + edge * layout(:exporter, :importer) + network()
plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)), network())

“Given trade partners: edges derived by layout from exporter to importer, in the network.”

The 15 countries get 15 positions on the panel, and gog draws one stroke for each of the 22 rows. Five pairs of countries trade in both directions, and each pair’s two strokes lie on one line. So you can count only 17 lines, and those five look slightly darker than the rest. No country is labeled: the layout placed the countries, but no layer draws their names.

An edge draws in two spaces only, network() and space(). A layout computes its positions from the graph. Here a graph is not a chart: it is a set of things and the relations between them. Each thing is a node, and each row is one relation between two nodes. A node is one name, however many rows it appears in: Germany is one node in seven rows. A layout counts each row as one step between its two nodes. Two countries that trade are one step apart, so they are placed close together, and nodes with more steps between them are placed farther apart. No column holds a node’s position, and turning or flipping the picture changes no distance, so a position on its own means nothing. In every other space, a position means something: a value on an axis, a place on the earth, or a share of a whole, so gog refuses an edge there. In the cube that space() draws, the box around the network carries no numbers, so a position is not read as a value there either.

A layout is not for edges alone. It gives every node one position. It also writes two columns. name holds each node’s name, and degree holds the number of rows the node appears in. Two other marks read a layout and draw at those same positions:

Mark derived by layout Shape
point * layout one dot per node
text * layout + label(name) each node’s name
edge * layout one stroke per relation, the plot above

The first plot names no country. The plot below draws all three marks, and it uses both columns the layout writes. size(degree) draws a node’s dot larger when the node appears in more rows. label(name) draws each node’s name, and repel moves each name off the dots and off the other names:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) +
  edge * layout(exporter, importer) +
  point * layout(exporter, importer) + size(degree) +
  text * layout(exporter, importer) * repel + label(name) +
  network() +
  title("Each node, sized by its degree")
(data(trade_partners) +
  edge * layout(col.exporter, col.importer) +
  point * layout(col.exporter, col.importer) + size(col.degree) +
  text * layout(col.exporter, col.importer) * repel + label(col.name) +
  network() +
  title("Each node, sized by its degree"))
data(trade_partners) + edge * layout(:exporter, :importer) +
  point * layout(:exporter, :importer) + size(:degree) +
  text * layout(:exporter, :importer) * repel + label(:name) + network() +
  title("Each node, sized by its degree")
plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)),
  layer(point, layout(col.exporter, col.importer)), size(col.degree),
  layer(text, layout(col.exporter, col.importer), repel), label(col.name),
  network(), title("Each node, sized by its degree"))

“Given trade partners: edges derived by layout from exporter to importer, and also points derived by layout from exporter to importer, sized by degree, and also text derived by layout from exporter to importer and repel, label by name, in the network.”

China appears in nine rows, the United States in eight and Germany in seven. No other country appears in more than three, so these three have the largest dots. A pair that trades both ways is two rows but one line, so only seven lines end at China’s dot.

Each layer computes the layout for itself. A layout uses no random numbers, so the same two columns always give the same positions in the plane. That is why every dot is exactly where its strokes end. The Network chapter draws this plot again, in The nodes and their names.

The next section draws each stroke with an opacity, a width, a color or a stroke pattern from its own row.

21.2 Opacity, width, color and pattern, one per row

In the plots above, every stroke is drawn the same way, so a relation worth 500 billion dollars looks like one worth 50 billion. Each edge is drawn from one row, so it can take its opacity, its width, its color and its stroke pattern from that row’s values. On an edge, size is the width of the stroke. opacity and size show a continuous column such as billions, the value of each relation, and the first plot maps it to opacity. A faint stroke’s ends are hard to find, so the plot keeps the point * layout(exporter, importer) layer, which draws a dot at each node:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) +
  edge * layout(exporter, importer) + opacity(billions) +
  point * layout(exporter, importer) +
  network() +
  title("More trade, darker stroke")
(data(trade_partners) +
  edge * layout(col.exporter, col.importer) + opacity(col.billions) +
  point * layout(col.exporter, col.importer) +
  network() +
  title("More trade, darker stroke"))
data(trade_partners) + edge * layout(:exporter, :importer) +
  opacity(:billions) + point * layout(:exporter, :importer) + network() +
  title("More trade, darker stroke")
plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)), opacity(col.billions),
  layer(point, layout(col.exporter, col.importer)), network(),
  title("More trade, darker stroke"))

“Given trade partners: edges derived by layout from exporter to importer, opacity by billions, and also points derived by layout from exporter to importer, in the network.”

The three darkest strokes meet at one node. This plot draws no names, but every node is at the same position as in the plot with names, in The network diagram. So the node where they meet is the United States. China, Mexico and Canada each export more than 400 billion dollars of goods to it.

The width of a stroke can come from its row in the same way. size(billions) draws a stroke wider where the relation is worth more:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) +
  edge * layout(exporter, importer) + size(billions) +
  point * layout(exporter, importer) +
  network() +
  title("More trade, wider stroke")
(data(trade_partners) +
  edge * layout(col.exporter, col.importer) + size(col.billions) +
  point * layout(col.exporter, col.importer) +
  network() +
  title("More trade, wider stroke"))
data(trade_partners) + edge * layout(:exporter, :importer) +
  size(:billions) + point * layout(:exporter, :importer) + network() +
  title("More trade, wider stroke")
plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)), size(col.billions),
  layer(point, layout(col.exporter, col.importer)), network(),
  title("More trade, wider stroke"))

“Given trade partners: edges derived by layout from exporter to importer, sized by billions, and also points derived by layout from exporter to importer, in the network.”

The three widest strokes are the three darkest in the plot above, and they meet at the United States. The legend draws a line at three values: 50, 275 and 500 billion dollars. Width also keeps the smallest relations in view: France to Spain, worth 50 billion, is a thin stroke here, and nearly disappears in the opacity plot.

On line, size and opacity are only settings: gog keeps one width and one opacity for a whole line (Stroke width and opacity). An edge draws one stroke per row, so each row gives its stroke a width and an opacity of its own.

Which exports come from each continent? On an edge, color needs a categorical column. The continent column holds the continent of each row’s exporter, and it has four values. A continuous column such as billions is refused there; map it to opacity or size, as above. The names are written in this plot, so you can see which two countries each stroke joins:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) +
  edge * layout(exporter, importer) + color(continent) +
  point * layout(exporter, importer) +
  text * layout(exporter, importer) * repel + label(name) +
  network() +
  title("Each stroke, colored by its exporter's continent")
(data(trade_partners) +
  edge * layout(col.exporter, col.importer) + color(col.continent) +
  point * layout(col.exporter, col.importer) +
  text * layout(col.exporter, col.importer) * repel + label(col.name) +
  network() +
  title("Each stroke, colored by its exporter's continent"))
data(trade_partners) + edge * layout(:exporter, :importer) +
  color(:continent) + point * layout(:exporter, :importer) +
  text * layout(:exporter, :importer) * repel + label(:name) + network() +
  title("Each stroke, colored by its exporter's continent")
plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)), color(col.continent),
  layer(point, layout(col.exporter, col.importer)),
  layer(text, layout(col.exporter, col.importer), repel), label(col.name),
  network(), title("Each stroke, colored by its exporter's continent"))

“Given trade partners: edges derived by layout from exporter to importer, colored by continent, and also points derived by layout from exporter to importer, and also text derived by layout from exporter to importer and repel, label by name, in the network.”

Europe’s strokes all touch Germany, except France’s stroke to Spain. The Americas’ strokes all touch the United States, except Brazil’s stroke to China. Oceania has one stroke, from Australia to China.

color(exporter) draws as well, with one color for each of the twelve exporters. Twelve colors are hard to distinguish on a stroke a pixel or two wide. Mexico, Canada and the Netherlands also get a color in the legend and on no stroke, because each trades with one partner only, and the partner’s row is drawn over theirs. With continent, four colors are easy to distinguish, and every color in the legend is on a stroke.

Strokes are drawn in row order, so where two countries trade both ways, the later row’s stroke covers the other. Between China and Germany, Germany’s row comes later, and the stroke shows mostly Europe’s color.

The stroke pattern can come from a column too. pattern(continent) gives each continent a stroke pattern, the way color(continent) gave each a color above:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) +
  edge * layout(exporter, importer) + pattern(continent) +
  point * layout(exporter, importer) +
  text * layout(exporter, importer) * repel + label(name) +
  network() +
  title("Each stroke, patterned by its exporter's continent")
(data(trade_partners) +
  edge * layout(col.exporter, col.importer) + pattern(col.continent) +
  point * layout(col.exporter, col.importer) +
  text * layout(col.exporter, col.importer) * repel + label(col.name) +
  network() +
  title("Each stroke, patterned by its exporter's continent"))
data(trade_partners) + edge * layout(:exporter, :importer) +
  pattern(:continent) + point * layout(:exporter, :importer) +
  text * layout(:exporter, :importer) * repel + label(:name) + network() +
  title("Each stroke, patterned by its exporter's continent")
plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)), pattern(col.continent),
  layer(point, layout(col.exporter, col.importer)),
  layer(text, layout(col.exporter, col.importer), repel), label(col.name),
  network(), title("Each stroke, patterned by its exporter's continent"))

“Given trade partners: edges derived by layout from exporter to importer, patterned by continent, and also points derived by layout from exporter to importer, and also text derived by layout from exporter to importer and repel, label by name, in the network.”

The stroke patterns follow the order in which the continents first appear in the continent column: Asia’s strokes are solid, the Americas’ are dashed, Europe’s are dotted and Oceania’s are dotdash. Between China and Germany, Germany’s dotted stroke is drawn over China’s solid one, and the solid stroke shows through the gaps, so the line looks solid.

There are five stroke patterns: solid, dashed, dotted, dotdash and longdash. A column with more than five categories repeats them from the start.

21.3 Transforms it takes

A transform computes new values from the rows, and the mark draws those values instead of the rows. The table lists, by kind, the transforms an edge takes and the ones it refuses:

Kind Takes Refuses
Counting — bin, count, density, proportion
Summaries — sum, mean, median, max, min, quantile
Fitted lines — smooth, straight
Running total — cumulative
Pairs: a low and a high — range, confidence, deviation, smooth_band, straight_band, bounds
Collision modifiers — dodge, stack, jitter, repel
Layouts of a whole picture layout ● partition, flow, cluster

An edge takes one transform, layout. It is marked ●: gog cannot draw an edge without it, because without a layout an edge has no ends. The plots below show it twice: in the plane, and in a cube.

Layouts. layout places each node once, and an edge draws one stroke between the two nodes of each row. It needs network() or space(), where no axis carries numbers, because a node’s position is not a value on any axis. network() places the nodes in the plane, as every plot above does. Write space() in its place, here with a viewing angle, space(turn = 35, tilt = 20), and the layout places them in a cube instead. Both numbers are degrees, and The viewing angle explains them. A point layer draws a dot at each node, so the ends of each stroke are easy to find:

  • R
  • Python
  • Julia
  • JavaScript
((data(trade_partners) + edge * layout(exporter, importer) +
    point * layout(exporter, importer) + network() + title("edge * layout")) |
   (data(trade_partners) + edge * layout(exporter, importer) +
      point * layout(exporter, importer) + space(turn = 35, tilt = 20) +
      title("edge * layout, in a cube"))) +
  theme(height = 420)
(((data(trade_partners) + edge * layout(col.exporter, col.importer) +
    point * layout(col.exporter, col.importer) + network() + title("edge * layout")) |
   (data(trade_partners) + edge * layout(col.exporter, col.importer) +
      point * layout(col.exporter, col.importer) + space(turn = 35, tilt = 20) +
      title("edge * layout, in a cube"))) +
  theme(height = 420))
((data(trade_partners) + edge * layout(:exporter, :importer) +
  point * layout(:exporter, :importer) + network() +
  title("edge * layout")) |
  (data(trade_partners) + edge * layout(:exporter, :importer) +
  point * layout(:exporter, :importer) + space(turn = 35, tilt = 20) +
  title("edge * layout, in a cube"))) + theme(height = 420)
beside(plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)),
  layer(point, layout(col.exporter, col.importer)), network(),
  title("edge * layout")),
  plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)),
  layer(point, layout(col.exporter, col.importer)),
  space({ turn: 35, tilt: 20 }), title("edge * layout, in a cube")),
  theme({ height: 420 }))

“Given trade partners: edges derived by layout from exporter to importer, and also points derived by layout from exporter to importer, in the network, beside the same in the cube, turned 35, tilted 20.”

The cube holds the same 22 strokes. Every node takes a new position in the cube, because the layout places the nodes in three directions instead of two. The Network chapter names each node in the cube, in The network in the cube, and shows how to turn it with a drag in the web edition.

An edge refuses every transform in the Refuses column above. Most of them compute a value to place on an axis, or move a mark along one, and an edge has no axis. The other three, in the same row of the table as layout, compute shapes for different marks: partition gives rectangles to a zone, flow gives bands to a ribbon, and cluster gives branches to a path.

21.4 What you can set

Some choices come from no column: how thick every stroke is, or one stroke pattern for all of them. You set those in the sentence, with style(), and each mark takes its own settings. Setting vs mapping shows how a setting differs from mapping a column. These are an edge’s settings, with the values each accepts:

Setting Value
style(color = ) any CSS color name or hex
style(opacity = ) 0 to 1
style(size = ) pixels
style(pattern = ) solid, dashed, dotted, dotdash, longdash
style(arrow = ) end, start, both

style(size = ), style(color = ), style(opacity = ) and style(pattern = ) give every stroke the same value. A mapping such as size(billions) gives each stroke its own. The settings table above lists every stroke pattern that style(pattern = ) accepts.

One layer cannot both map a channel and set it. gog refuses this sentence, which maps continent to color and also sets the color to red:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) + edge * layout(exporter, importer) + color(continent) +
  style(color = "red") + network()
(data(trade_partners) + edge * layout(col.exporter, col.importer) + color(col.continent) +
  style(color = "red") + network())
data(trade_partners) + edge * layout(:exporter, :importer) +
  color(:continent) + style(color = "red") + network()
plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)), color(col.continent),
  style({ color: "red" }), network())
Error:
! gog: `color(continent)` maps color and `style(color = "red")` sets it — one layer cannot do both. Keep `color(continent)` to show the data, or `style(color = "red")` to fix every edge at one value.
gog: nothing was rendered. Fix the above, or set GOG_STRICT=0 to draw anyway.

The message names two fixes: keep color(continent) to show the data, or style(color = "red") to give every edge one color.

style(arrow = ) draws an arrowhead on each stroke. With "end", it is at the node in the second column of layout(), the to column. With "start", it is at the node in the first column, and with "both", at both nodes. Each arrowhead ends outside the dot that a point * layout layer draws at the node, so the dot does not cover it:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) +
  edge * layout(exporter, importer) + style(arrow = "end") +
  point * layout(exporter, importer) +
  network() +
  title("Each stroke points at its importer")
(data(trade_partners) +
  edge * layout(col.exporter, col.importer) + style(arrow = "end") +
  point * layout(col.exporter, col.importer) +
  network() +
  title("Each stroke points at its importer"))
data(trade_partners) + edge * layout(:exporter, :importer) +
  style(arrow = "end") + point * layout(:exporter, :importer) +
  network() + title("Each stroke points at its importer")
plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)),
  style({ arrow: "end" }),
  layer(point, layout(col.exporter, col.importer)), network(),
  title("Each stroke points at its importer"))

“Given trade partners: edges derived by layout from exporter to importer, with arrow end, and also points derived by layout from exporter to importer, in the network.”

The grid of every mark and every setting shows which other marks share this list. What a mark maps rather than sets is its row on the grid of marks and channels.

21.5 What it refuses

The other marks take their positions from x and y, so you may try binding x and y to an edge. Only a layout places an edge’s two ends. With x and y and no layout, the edge has nothing to draw, so gog refuses the sentence:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) + edge + x(billions) + y(exporter)
data(trade_partners) + edge + x(col.billions) + y(col.exporter)
data(trade_partners) + edge + x(:billions) + y(:exporter)
plot(data(trade_partners), edge, x(col.billions), y(col.exporter))
Error:
! gog: an `edge` connects two nodes, and only `layout` places them, so an `edge` with no `layout` has nothing to draw. Name the two endpoint columns and draw it in the network: `edge * layout(<from>, <to>) + network()`.
gog: nothing was rendered. Fix the above, or set GOG_STRICT=0 to draw anyway.

The message shows what to write instead: name the two endpoint columns in layout() and draw it in network().

A layout computes its positions from the graph, and no column holds them, so an axis has no value to show for them. Without network(), a sentence is in the plane, and the plane has axes. So gog refuses this sentence, which leaves network() out:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) + edge * layout(exporter, importer)
data(trade_partners) + edge * layout(col.exporter, col.importer)
data(trade_partners) + edge * layout(:exporter, :importer)
plot(data(trade_partners),
  layer(edge, layout(col.exporter, col.importer)))
Error:
! gog: a `layout`'s positions are the graph's, not the data's — an axis under them would number something no reader can mean. Draw it flat with `+ network()`, or in the cube with `+ space(turn = 30, tilt = 25)`.
gog: nothing was rendered. Fix the above, or set GOG_STRICT=0 to draw anyway.

The message gives two ways to draw it: flat with + network(), or in the cube with + space(turn = 30, tilt = 25).

The Network chapter shows four more refusals: a mark other than edge, point or text with * layout, an x() in a sentence with a layout, network() with no layout, and a row from a node to itself. It explains why a brush is refused there too.

21.6 What comes next

An edge never has an axis, because a layout places both of its endpoints. Most other marks are placed by their values on the axes. Scales shows how a value becomes a position on an axis.
