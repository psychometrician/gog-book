11  Area

How large was the quantity at each date? area fills the region between the data and a baseline at zero. Its top edge is the boundary a line would draw, and the fill below that edge shows how large the quantity was.

11.1 Basic usage

How large were sales in each of five years? The actuals table holds the sales of one year in each row, from 2019 to 2023. Most examples in this chapter start from the smallest sentence that draws an area: the data, the mark, and its two positions, x and y.

actuals: all 5 rows
year sales
2019 120
2020 135
2021 128
2022 152
2023 168
  • R
  • Python
  • Julia
  • JavaScript
data(actuals) + area + x(year) + y(sales) +
  y_label("Sales") + title("Sales, 2019 to 2023")
(data(actuals) + area + x(col.year) + y(col.sales) +
  y_label("Sales") + title("Sales, 2019 to 2023"))
data(actuals) + area + x(:year) + y(:sales) + y_label("Sales") +
  title("Sales, 2019 to 2023")
plot(data(actuals), area, x(col.year), y(col.sales), y_label("Sales"),
  title("Sales, 2019 to 2023"))

“Given the actuals: an area, x is year, y is sales.”

Notice that the fill reaches the left and right edges of the panel. With point, the axis ends a little past the data. A dot drawn at the last value would otherwise be cut in half by the panel edge. An area has no dots. Its top edge passes through the data values, so nothing can be cut off, and the axis ends exactly at the first and last year. Scales explains when an axis ends at the data and when it leaves a margin.

An area’s two axes do different jobs. One is the domain, the axis the area runs along, and the other is the measure, the quantity it fills up to. A line has the same two axes. When one of a bar’s two columns is a category, swapping the columns on x and y turns the bar on its side. In the plot above both columns are numbers, so the domain is x. A category is always the domain, on either axis, so an area turns as a bar does. With the category on y, it is read down the page and fills toward zero on x, as A category on the domain shows. density reads a category differently: its curve runs along the axis that does not hold the category, and With transforms shows both forms, the half violin and the ridgeline plot.

11.2 Why the fill starts at zero

A line says where the value was; an area says how much there was. The fill is the quantity, so it starts from zero. A fill that starts anywhere else shows the height above that start, not the quantity itself. gog does not stop you from starting the axis somewhere else. y(sales, limits = c(100, NA)) starts it at 100, and the NA leaves the top where the data puts it. That code is R; the chapters for Python, Julia and JavaScript show it in their own spelling. The fill starts at 100 too, and no warning is printed. That decision is yours to make: the fill then shows sales minus 100 rather than the sales, and whoever reads your plot has to know it. Scales explains limits.

So the choice of mark is about the data, not the appearance. Sales have a true zero, where zero means none at all, so the first plot is correct: the fill is the sales. Life expectancy in years has a true zero too, and several plots below fill to it. A quantity whose zero is only a convention has no amount for a fill to show. A temperature in degrees Celsius is one: 0 °C is where water freezes, not the absence of heat. A calendar year is another: the year 0 is not the absence of time. Draw those with line.

For life expectancy the data allows either mark, so the question you are asking decides between them. An area and a line draw the same top edge. Here is that edge drawn with line and split by color, as in the Line chapter. It shows where each country’s value was, and nothing about how much:

11.3 Multiple series

The table holds five countries, twelve years each, so the sentence has to name the column that splits them. Without a split, the boundary runs through all sixty rows as one region. color splits the rows into one series per country, the rows that one region is drawn through, and names each country in a legend. It is the same split that gives line one stroke per country. The sentence also sets a low opacity, so the regions drawn first show through the ones drawn over them:

  • R
  • Python
  • Julia
  • JavaScript
data(gapminder_asia) + area + x(year) + y(life) + color(country) +
  style(opacity = 0.45) +
  title("One region per country")
(data(gapminder_asia) + area + x(col.year) + y(col.life) + color(col.country) +
  style(opacity = 0.45) +
  title("One region per country"))
data(gapminder_asia) + area + x(:year) + y(:life) + color(:country) +
  style(opacity = 0.45) + title("One region per country")
plot(data(gapminder_asia), area, x(col.year), y(col.life),
  color(col.country), style({ opacity: 0.45 }),
  title("One region per country"))

“Given gapminder Asia: areas, x is year, y is life, color by country, with opacity 0.45.”

Five lines can cross without hiding each other, because a line is a thin stroke. Five areas cannot: a fill covers whatever lies behind it, and at the default opacity, 0.82, only a little shows through. Write the same sentence with no opacity, and gog prints a warning before it draws:

  • R
  • Python
  • Julia
  • JavaScript
data(gapminder_asia) + area + x(year) + y(life) + color(country) +
  title("Five regions, no opacity set: each one covers the ones before it")
(data(gapminder_asia) + area + x(col.year) + y(col.life) + color(col.country) +
  title("Five regions, no opacity set: each one covers the ones before it"))
data(gapminder_asia) + area + x(:year) + y(:life) + color(:country) +
  title("Five regions, no opacity set: each one covers the ones before it")
plot(data(gapminder_asia), area, x(col.year), y(col.life),
  color(col.country),
  title("Five regions, no opacity set: each one covers the ones before it"))
gog: `area` split by `country` draws 5 regions on top of one another, and the last one drawn can hide the rest. Add `style(opacity = 0.5)` to see through them, or use `line` to compare shapes without filling.

“Given gapminder Asia: areas, x is year, y is life, color by country.”

Compare the legend with the plot. Every country is named there, but five regions cannot be distinguished. Each region covers the ones drawn before it, so you can read a region only where it rises above every region drawn after it. The warning is advice rather than a refusal: the sentence is legal, so gog draws it.

The other way to draw it is to stack the regions instead of overlaying them. That is written area * stack. stack is a collision modifier: it moves marks that would otherwise be drawn in the same place, rather than summarizing them. The other three move single marks: dodge sets them side by side within a category’s slot, the stretch of the axis that belongs to one category, jitter scatters them, and repel pushes labels apart. An area is one connected shape across the axis, not a single mark, so it refuses all three. With stack, each region starts at the top of the ones below it, so the five form one stacked shape and none is covered:

  • R
  • Python
  • Julia
  • JavaScript
data(gapminder_asia) + area * stack + x(year) + y(population) + color(country) +
  y_label("Population") +
  title("Five Asian countries, population stacked")
(data(gapminder_asia) + area * stack + x(col.year) + y(col.population) + color(col.country) +
  y_label("Population") +
  title("Five Asian countries, population stacked"))
data(gapminder_asia) + area * stack + x(:year) + y(:population) +
  color(:country) + y_label("Population") +
  title("Five Asian countries, population stacked")
plot(data(gapminder_asia), layer(area, stack), x(col.year),
  y(col.population), color(col.country), y_label("Population"),
  title("Five Asian countries, population stacked"))

“Given gapminder Asia: areas derived by stack, x is year, y is population, color by country.”

Each country’s region is as thick as its population, and the top edge of the stack is the five-country total. This plot measures population instead of life on purpose. You stack quantities that add: populations add up to a total that means something, and life expectancies do not. gog does not stop you from stacking them. Put y(life) in place of y(population) in the sentence above, and gog draws five regions to a top edge that climbs from 229 in 1952 to 370 in 2007, with no warning. That number means nothing. So use stack with care: you always get a plot, and only you know whether the sum of the parts means something.

Which country’s share of the five grew? The stacked plot cannot say, because every region’s baseline moves with the ones below it. stack(share = TRUE) divides each country’s value in a year by that year’s total. The top edge of the stack is then flat at 1, and each region’s thickness is that country’s share:

  • R
  • Python
  • Julia
  • JavaScript
data(gapminder_asia) + area * stack(share = TRUE) + x(year) + y(population) +
  color(country) +
  y_label("Share of population") +
  title("Five Asian countries, population as shares")
(data(gapminder_asia) + area * stack(share = True) + x(col.year) + y(col.population) +
  color(col.country) +
  y_label("Share of population") +
  title("Five Asian countries, population as shares"))
data(gapminder_asia) + area * stack(share = true) + x(:year) +
  y(:population) + color(:country) + y_label("Share of population") +
  title("Five Asian countries, population as shares")
plot(data(gapminder_asia), layer(area, stack({ share: true })),
  x(col.year), y(col.population), color(col.country),
  y_label("Share of population"),
  title("Five Asian countries, population as shares"))

“Given gapminder Asia: areas derived by stack as shares, x is year, y is population, color by country.”

Between 1952 and 2007, India’s share rose from 0.33 to 0.39, and Japan’s fell from 0.08 to 0.05. The total is gone from this plot: every year reaches 1, so it shows which shares grew and no longer how large the total was. Draw both when you need both answers. The Transforms chapter covers stack in full, with a section on stacked areas.

Every stack so far was split by color. A stack can also be split by group. It splits the rows as color does, but every region gets the same color and there is no legend. Use it when the total matters more than telling the regions apart. Because the regions share one color, gog draws a thin line between them in the panel’s background color. A stacked bar separates its segments the same way. The channel_sales table holds each quarter’s revenue from two ways of selling. Its channel column names them, Retail and Online:

channel_sales: first 5 of 6 rows
quarter channel revenue
Q1 Retail 4
Q1 Online 3
Q2 Retail 5
Q2 Online 6
Q3 Retail 4
  • R
  • Python
  • Julia
  • JavaScript
data(channel_sales) + area * stack + x(quarter) + y(revenue) + group(channel)
data(channel_sales) + area * stack + x(col.quarter) + y(col.revenue) + group(col.channel)
data(channel_sales) + area * stack + x(:quarter) + y(:revenue) +
  group(:channel)
plot(data(channel_sales), layer(area, stack), x(col.quarter),
  y(col.revenue), group(col.channel))

“Given the channel sales table: areas derived by stack, x is quarter, y is revenue, grouped by channel.”

quarter is a category, so each quarter gets a slot of its own, and the fill runs from the middle of the first slot to the middle of the last. So half a slot is left empty at each end. On a continuous axis, as in Basic usage, the fill reaches both edges of the panel. A category on the domain describes this shape.

The top edge is each quarter’s total. Retail comes first in the table, and gog piles the series in that order, so Retail is the lower region. The thin line marks where the retail region ends and the online region begins. No color or legend tells the two regions apart. When the reader needs to know which is which, split by color instead, which gives each region its own fill and a legend entry. The thin line is not a border: an area takes no border, as the next section explains. gog draws the line only when group alone splits the stack, and no setting removes it.

11.4 Giving an area an edge

A low opacity, like the 0.45 in Multiple series, leaves a faint top edge, and the top edge is where the data is. A stroke along it makes the boundary easy to read. An area takes no border of its own. To draw the edge, layer a line over the area; the line traces the same top edge:

  • R
  • Python
  • Julia
  • JavaScript
data(actuals) + x(year) + y(sales) +
  area + style(color = "steelblue", opacity = 0.25) +
  line + style(color = "steelblue", size = 2.5) +
  title("area + line: the fill and its edge, composed")
(data(actuals) + x(col.year) + y(col.sales) +
  area + style(color = "steelblue", opacity = 0.25) +
  line + style(color = "steelblue", size = 2.5) +
  title("area + line: the fill and its edge, composed"))
data(actuals) + x(:year) + y(:sales) + area +
  style(color = "steelblue", opacity = 0.25) + line +
  style(color = "steelblue", size = 2.5) +
  title("area + line: the fill and its edge, composed")
plot(data(actuals), x(col.year), y(col.sales), area,
  style({ color: "steelblue", opacity: 0.25 }), line,
  style({ color: "steelblue", size: 2.5 }),
  title("area + line: the fill and its edge, composed"))

“Given the actuals: x is year, y is sales, an area and also a line.”

There is no border setting on area to use instead. A layered line gives the edge its own color, width, opacity and stroke pattern. A bar’s border settings, border_color and border_size, give only a color and a width.

11.5 One region, one fill

The plot above set one opacity for the whole area. Can you map a column to an area’s opacity instead? No, whether the column is a category or a number. On an area, opacity belongs to the layer, not to each region: every region in the layer has the same opacity. So opacity is a setting here and not a channel. One region cannot be lighter in one year and darker in another, and one country’s region cannot be lighter than another’s. The table in Two questions, not one shows, for every mark, which properties belong to the layer in the same way.

color is different, because it belongs to each region. A categorical column gives each region its own color. One region still has one color, so a continuous column, which would change the color within a region, is refused. What it refuses shows both refusals.

The allowed form is the plot from Multiple series, drawn again here: one color for each country’s region, and one opacity, 0.45, for the whole layer:

  • R
  • Python
  • Julia
  • JavaScript
data(gapminder_asia) + area + x(year) + y(life) + color(country) +
  style(opacity = 0.45) +
  title("One region per country")
(data(gapminder_asia) + area + x(col.year) + y(col.life) + color(col.country) +
  style(opacity = 0.45) +
  title("One region per country"))
data(gapminder_asia) + area + x(:year) + y(:life) + color(:country) +
  style(opacity = 0.45) + title("One region per country")
plot(data(gapminder_asia), area, x(col.year), y(col.life),
  color(col.country), style({ opacity: 0.45 }),
  title("One region per country"))

“Given gapminder Asia: areas, x is year, y is life, color by country, with opacity 0.45.”

line also takes opacity only as a setting (Stroke width and opacity).

size is refused both ways: area neither maps it nor sets it. A stroke has a width, so line lets you set one. An area’s extent comes from its x, its y and its baseline, so there is no size to choose. Both marks take style(color = ) and style(opacity = ). What it refuses shows the refusal for size as well.

11.6 With transforms

Apart from the stack, every plot so far filled to values already in the table. A transform computes new values first, and the area fills to what it computed. A distribution, for example, can be drawn as a filled shape. The question is the one a histogram answers: how many rows fall in each interval? bin, density and the aggregation family mean the same thing on an area as on a bar. bin counts the rows in each interval. The boundary then runs through the bin centers, and the region below it is filled. That shape is the frequency polygon line * bin draws, with its inside filled:

bin(30) and bin(width = 5) set the bins here exactly as they do for a bar: bin(30) cuts the axis into 30 intervals, and bin(width = 5) into intervals five years wide. The two plots below draw both, one above the other, so they share the life axis:

  (data(gapminder_2007) + area * bin(30) + x(col.life) +
     x_label("Life expectancy (years)") + title("area * bin(30)")))

  title("area * bin(width = 5)")) /
  (data(gapminder_2007) + area * bin(30) + x(:life) +
  x_label("Life expectancy (years)") + title("area * bin(30)"))

  x(col.life), title("area * bin(width = 5)")),

  x_label("Life expectancy (years)"), title("area * bin(30)")))

“Given gapminder 2007: an area derived by bin at width 5, x is life, above an area derived by bin into 30, x is life.”

With five-year bins, the boundary is smooth and has one clear peak: 39 countries between 70 and 75 years. Thirty bins follow every small rise and fall. One of them, between 68 and 70 years, holds no country, so the boundary drops to zero there. Choosing the bin count shows both, and Choosing a width explains how to pick a width.

density replaces the counts with a smooth curve, and the area fills the region under it:

  • Python
  • Julia
  • JavaScript
data(gapminder_2007) + area * density + x(life) +
  x_label("Life expectancy (years)") +
  title("area * density")
(data(gapminder_2007) + area * density + x(col.life) +
  x_label("Life expectancy (years)") +
  title("area * density"))
data(gapminder_2007) + area * density + x(:life) +
  x_label("Life expectancy (years)") + title("area * density")
plot(data(gapminder_2007), layer(area, density), x(col.life),
  x_label("Life expectancy (years)"), title("area * density"))

“Given gapminder 2007: an area derived by density, x is life.”

density is not the area’s own transform. Other marks take it too, and only the shape changes:

Mark derived by density Shape
line * density the curve as a stroke
step * density the curve as a staircase
point * density one dot at each point where the curve was estimated
bar * density one thin bar at each of those points
ribbon * density with a category, the curve mirrored: the violin
area * density the curve filled to the baseline, the plot above

Put line, step, point or bar in place of area in the sentence above, and each one draws. ribbon refuses it, because a ribbon spans between two boundaries and one curve gives only one. With a category, ribbon * density + x(<category>) + y(<measure>) draws the violin.

Give the area * density sentence a category on x and a number on y, and the curve runs along y instead of x. Each continent gets its own estimate, drawn inside its slot. The curve is one side of the violin that ribbon * density draws, so this plot is called the half violin:

  • R
  • Python
  • Julia
  • JavaScript
data(gapminder_2007) + area * density + x(continent) + y(life) +
  color(continent) +
  y_label("Life expectancy") +
  title("area * density + x(continent): the half violin")
(data(gapminder_2007) + area * density + x(col.continent) + y(col.life) +
  color(col.continent) +
  y_label("Life expectancy") +
  title("area * density + x(continent): the half violin"))
data(gapminder_2007) + area * density + x(:continent) + y(:life) +
  color(:continent) + y_label("Life expectancy") +
  title("area * density + x(continent): the half violin")
plot(data(gapminder_2007), layer(area, density), x(col.continent),
  y(col.life), color(col.continent), y_label("Life expectancy"),
  title("area * density + x(continent): the half violin"))

“Given gapminder 2007: areas derived by density, x is continent, y is life, color by continent.”

The area * density + x(life) sentence above and this one differ in three places: x moved from life to continent, y(life) was added, and so was color(continent). With only x(life), life runs along x and y holds no column, so y carries the density estimate, as it carried the count for bin. With a category on x and a number on y, both axes hold a column, so each estimate is drawn across its category’s slot, one distribution per continent. The slots already keep the continents apart, so here color only paints: it gives each continent’s region its own fill and a legend entry, and without it the plot still draws one curve per continent, all in the same default color. On a line the same channel colors the stroke; on an area it colors the fill.

Can the two columns trade axes? Yes: a category can go on either axis. Put life on x and the category on y, and each curve runs along life, rising from its own category’s place on the y axis. That is the ridgeline plot, and it is the half violin’s sentence with x and y exchanged:

  • R
  • Python
  • Julia
  • JavaScript
data(gapminder_2007) + area * density + x(life) + y(continent) +
  color(continent) +
  x_label("Life expectancy") + title("area * density + x(life): the ridgeline")
(data(gapminder_2007) + area * density + x(col.life) + y(col.continent) +
  color(col.continent) +
  x_label("Life expectancy") + title("area * density + x(life): the ridgeline"))
data(gapminder_2007) + area * density + x(:life) + y(:continent) +
  color(:continent) + x_label("Life expectancy") +
  title("area * density + x(life): the ridgeline")
plot(data(gapminder_2007), layer(area, density), x(col.life),
  y(col.continent), color(col.continent), x_label("Life expectancy"),
  title("area * density + x(life): the ridgeline"))

“Given gapminder 2007: areas derived by density, x is life, y is continent, color by continent.”

Ribbon shows all four forms in one section: one side or two, and the category on either axis. Its violin section says what the width of a violin can mean.

Both shapes can also give each continent a panel of its own, with facet(). The strip above each panel names the continent, so the legend is left out. For the half violin, put the panels side by side with |, and write free = TRUE on x. Without it, every panel keeps all five continents’ slots, and each curve is squeezed into a fifth of its panel. With it, each panel’s axis is fitted to its own rows (Giving a panel its own scale), so the panel holds one slot. The widest half violin, Europe’s, fills its panel, and the others keep their widths relative to it, as in the half violin above, so Oceania’s two countries draw thin:

  • R
  • Python
  • Julia

11.8 Transforms it takes

A transform computes new values from the rows, and the mark draws those values instead of the rows. The table lists, by kind, the transforms an area takes and the ones it refuses:

Kind Takes Refuses
Counting bin, count, density, proportion —
Summaries sum, mean, median, max, min, quantile —
Fitted lines smooth, straight —
Running total cumulative —
Pairs: a low and a high — range, confidence, deviation, smooth_band, straight_band, bounds
Collision modifiers stack dodge, jitter, repel
Layouts of a whole picture — partition, flow, layout, cluster

11.9 What you can set

A setting changes how the region looks without reading a column, and each mark takes its own. Setting vs mapping shows how a setting differs from mapping a column. These are an area’s settings, with the values each accepts:

Setting Value
style(color = ) any CSS color name or hex
style(opacity = ) 0 to 1
style(pattern = ) solid, hatch, crosshatch, stripes, grid, dots

That is the shortest settings list in the book, shared with ribbon. line has one more, size, and bar has three more: border_color, border_size and gap. Each is left out on purpose: One region, one fill explains size, Giving an area an edge explains the border, and gap is a share of the slot a bar fills, and an area does not fill a slot. The one setting this chapter has not shown yet is pattern, a texture on the fill. The plot below hatches the fill and draws the edge with a layered line, as before:

  • Python
  • Julia
  • JavaScript
data(actuals) + x(year) + y(sales) +
  area + style(color = "seagreen", pattern = "hatch", opacity = 0.5) +
  line + style(color = "seagreen", size = 2) +
  y_label("Sales") + title("A textured fill, and a line for the edge")
(data(actuals) + x(col.year) + y(col.sales) +
  area + style(color = "seagreen", pattern = "hatch", opacity = 0.5) +
  line + style(color = "seagreen", size = 2) +
  y_label("Sales") + title("A textured fill, and a line for the edge"))
data(actuals) + x(:year) + y(:sales) + area +
  style(color = "seagreen", pattern = "hatch", opacity = 0.5) + line +
  style(color = "seagreen", size = 2) + y_label("Sales") +
  title("A textured fill, and a line for the edge")
plot(data(actuals), x(col.year), y(col.sales), area,
  style({ color: "seagreen", pattern: "hatch", opacity: 0.5 }), line,
  style({ color: "seagreen", size: 2 }), y_label("Sales"),
  title("A textured fill, and a line for the edge"))

“Given the actuals: x is year, y is sales, an area colored seagreen, with pattern hatch and opacity 0.5, and also a line colored seagreen, with size 2.”

That layered line traces only the top boundary. A border would also draw a line along the two sides and the baseline.

The grid of every mark and every setting shows which other marks share this list. What a mark maps rather than sets is its row on the grid of marks and channels.

11.10 What it refuses

gog refuses five kinds of area sentence: a category on both axes, bin on a category, a mapped opacity or a continuous color, any size, and a split that leaves one position in every series. The first two come from an axis. The first comes from the measure. A region fills to a baseline at zero, and a category has no zero, so one axis must hold a continuous column. With categories on both axes there is nothing to fill:

plot(data(gapminder_2007), area, x(col.continent), y(col.country))

A category on one axis alone is accepted, on either axis. On y, beside a number on x, the area turns down the page (A category on the domain), and with density it is the ridgeline plot in With transforms.

The second comes from the domain. bin cuts a continuous axis into intervals, and a category is one slot with no width to cut. The message names count, the transform that tallies the rows in each category:

density needs a continuous column too, because it estimates how the rows are spread along one. With that column alone, write it on x. 11.11 In short

An area reads a category as its domain, on either axis, as a bar does, so a category on y turns it down the page. With two numbers its domain is x. density reads a category on either axis as the slot its curve is drawn in. opacity belongs to the layer, and color to each region. Its extent comes from its x, its y and its baseline, so size is refused both ways.
