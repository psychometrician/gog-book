6  The book’s data

Where do gapminder_2007, medals and winds come from, and how do you get them?

Data was about a table of your own. This chapter is about the shared tables that the book’s examples draw from, listed in full under The tables. They are published beside the book as CSV files, one per table, so you can run any example in this book yourself. Each file has a fixed address:

https://psychometrician.github.io/gog-book/data/<name>.csv

gapminder_2007.csv holds the 142 countries drawn in the chapter A first plot. medals.csv holds the medal counts drawn in Reading practice, and winds.csv holds the wind observations drawn in Polar.

Reading one takes a single call, gog_table(), which is part of the gog package in all four languages. Nothing else needs to be installed.

gog_table() is a convenience: a quick way to read the book’s tables from the book’s website. It is not a tool for reading or preparing data, and you do not have to use it. A table you read yourself, with readr in R, pandas in Python or any other reader you already use, works the same in data(). Reading a table says what to check when you do.

6.1 Reading a table

To run the first chapter’s plot yourself, you need its table loaded in R, Python, Julia or JavaScript. One line fetches it. gog_table() reads any of these tables by name:

gapminder_2007: first 5 of 142 rows
country continent year life population gdp
Afghanistan Asia 2007 43.828 31889923 974.5803
Albania Europe 2007 76.423 3600523 5937.0295
Algeria Africa 2007 72.301 33333216 6223.3675
Angola Africa 2007 42.731 12420476 4797.2313
Argentina Americas 2007 75.320 40301927 12779.3796
  • R
  • Python
  • Julia
  • JavaScript
gapminder_2007 <- gog_table("gapminder_2007")
data(gapminder_2007) + point + x(gdp) + y(life)
gapminder_2007 = gog_table("gapminder_2007")
data(gapminder_2007) + point + x(col.gdp) + y(col.life)
gapminder_2007 = gog_table("gapminder_2007")
data(gapminder_2007) + point + x(:gdp) + y(:life)
const gapminder_2007 = await gog_table("gapminder_2007");
plot(data(gapminder_2007), point, x(col.gdp), y(col.life));

“Given gapminder 2007: points, x is gdp, y is life.”

Those four calls draw the same picture, because the table is the same file and the engine is the same program.

A CSV file stores every value as text, so gog_table() converts each column when it reads the file. A column becomes numbers when every value in it is a number. An empty cell or NA counts as a missing value, not as text, so a column of numbers with gaps still becomes numbers. Every other column stays text. This rule gives the right type for most columns. It gives the wrong type for a label written as a number, and for a date, which stays text. The text argument keeps a column as text. Ten columns in these tables need it, and Labels that look like numbers, below, explains which and why. gog_table() decides types this way so that the book’s examples run with nothing else installed. If you already use readr, pandas or another reader, set each column’s type there, where you can see and control it.

Why does a graphics package carry a table reader at all? R reads a CSV in one call, and Python and Julia in a few lines. JavaScript has no CSV reader in its standard library, and the work takes dozens of lines there, because a CSV reader cannot simply split each line on commas. Six countries in gapminder_2007.csv have a comma in the name, "Congo, Dem. Rep." among them, so that split gives those rows seven fields, while the header has six. Nobody should have to paste dozens of lines of parsing before drawing, so each package carries gog_table() instead.

Each package fetches the file with what its language already has: R’s read.csv(), urllib in Python, Downloads in Julia and fetch in JavaScript.

Read a file with a CSV reader of your own, and the rest of this chapter still applies, because data() takes any table already in memory. You then do two things yourself. First, check each column’s type: your CSV reader decides it, so the ten columns listed in Labels that look like numbers need whatever that reader offers for keeping a column as text. Second, declare the category order, because a CSV never records one. You declare it with factor() in R, a pandas Categorical in Python, a CategoricalArray in Julia, and ordered() in JavaScript. gog_table() does not declare the order either, so after it, too, you declare the order yourself. Three things a CSV cannot record covers both, and dates as well.

Reading a different table is the same call with a different name: gog_table("winds"), gog_table("medals"). gog_table() refuses a misspelled name, and its message suggests the nearest published name, or points to the list under The tables.

6.2 Three things a CSV cannot record

A CSV records the values in a column, and never says what kind of column it is. Three kinds of information are therefore lost when the file is written. You restore them when you read the file. Each one changes the plot: the order of the categories, whether an axis has one slot per value, and whether an axis is a calendar. This chapter explains each one.

Restoring them is data preparation, and the tools you already use for your data do it best: readr and factor() in R, pandas in Python, CSV.jl and CategoricalArrays in Julia. This chapter shows how the book’s own tables get them only because gog_table() exists to read those tables quickly. For your own data, do this work with those tools, before the table reaches data().

6.2.1 A declared order

The eight compass points have a fixed order, and a plot of them reads correctly only when its axis keeps that order. The winds table records one wind observation per row:

winds: first 5 of 264 rows
direction bearing speed season
N 19.612260 10.1 Winter
N 357.049499 11.0 Winter
N 349.709737 13.8 Winter
N 2.602499 7.4 Winter
N 338.210715 3.7 Summer

The direction column of winds holds the eight compass points. Their order is N, NE, E, SE, S, SW, W, NW, clockwise from north. The Data chapter shows how a declared order sets the axis, the color assignment and the legend. A CSV cannot record that declaration. gog_table("winds") therefore reads direction as plain text, so you declare the order yourself after reading the file.

Until you declare an order, gog places the categories in the order they first appear in the rows. The winds file lists its rows in compass order, so a plot of direction made without the declaration reads correctly. Sort the rows by speed, and the axis shows S, N, NE, NW, SE, E, SW, W. The plot still draws, and nothing on it shows that the compass is in the wrong order.

The example below reads the table, sorts it by speed so that the rows are no longer in compass order, and then declares the compass order:

  • R
  • Python
  • Julia
  • JavaScript
winds <- gog_table("winds")
# `base::order`, because gog's `order()` masks it
winds <- winds[base::order(winds$speed), ]
compass <- c("N", "NE", "E", "SE", "S", "SW", "W", "NW")
winds$direction <- factor(winds$direction, levels = compass)

data(winds) + bar * count + x(direction)
import pandas as pd

winds = gog_table("winds")
by_speed = sorted(enumerate(winds["speed"]), key=lambda pair: pair[1])
winds = {name: [column[i] for i, _ in by_speed]
         for name, column in winds.items()}
compass = ["N", "NE", "E", "SE", "S", "SW", "W", "NW"]
winds["direction"] = pd.Categorical(winds["direction"], categories=compass)

data(winds) + bar * count + x(col.direction)
using CategoricalArrays

winds = gog_table("winds")
by_speed = sortperm(winds["speed"])
winds = Dict{String,Any}(name => column[by_speed] for (name, column) in winds)
compass = ["N", "NE", "E", "SE", "S", "SW", "W", "NW"]
winds["direction"] = CategoricalArray(winds["direction"]; levels = compass)

data(winds) + bar * count + x(:direction)
const winds = await gog_table("winds");
const by_speed = winds.speed.map((_, i) => i)
  .sort((a, b) => winds.speed[a] - winds.speed[b]);
for (const name in winds) winds[name] = by_speed.map((i) => winds[name][i]);
const compass = ["N", "NE", "E", "SE", "S", "SW", "W", "NW"];
winds.direction = ordered(winds.direction, compass);

plot(data(winds), layer(bar, count), x(col.direction));

“Given the winds: bars derived by count, x is direction.”

The rows are in speed order, and the axis still reads N to NW. The declared order decides the axis, not the order of the rows. A declared order is also kept when the plot is drawn in another space, such as a circle. The polar chapter draws these same counts of winds per direction as a wind rose, and the change is one word. Add polar(), and the axis is drawn as a circle, with N at the top and the rest clockwise from it:

  • R
  • Python
  • Julia
  • JavaScript
data(winds) + bar * count + x(direction) + polar()
data(winds) + bar * count + x(col.direction) + polar()
data(winds) + bar * count + x(:direction) + polar()
plot(data(winds), layer(bar, count), x(col.direction), polar())

“Given the winds: bars derived by count, x is direction, in polar.”

The polar chapter explains that plot. The circle starts at the first category and runs clockwise through the rest, so the compass reads correctly in the flat plot and in the circle.

The example sorts the rows only to take them out of compass order, so that you can see the declaration still works. The sort does not change the plot, so in your own code you need only the declaration.

A file that already lists its values in order still needs the declaration. Without it, the plot keeps that order only until you sort the rows, as the example above did. It is also lost when a sentence uses order(), which sorts undeclared text alphabetically. (Given a column of numbers, order() sorts by size instead; the labels in this list are text, so they are sorted alphabetically.) On the unsorted winds file, order(direction) puts the compass points in the order E, N, NE, NW, S, SE, SW, W. For most columns in this list, alphabetical order is also wrong: 10th comes before 1st, 10 comes before 2, and Ambient comes before Folk. The next section shows what happens to census without its declaration.

6.2.2 Labels that look like numbers

The second thing a CSV cannot record is which columns are text. Ten columns in these tables hold labels written as numbers, and gog_table() reads each of them as numbers unless you name it in the text argument. Eight of their tables are in the list above. The other two are new: eras holds the outline of every country, with its life expectancy in 1957 and 2007. ohio_turnout holds the share of each Ohio county’s citizens who voted in three elections. The list below names the ten columns.

Without the text argument, age becomes numbers. A point or a line then places the bands along a continuous axis from 0 to 85, with ticks at 0, 20, 40, 60 and 80. No band gets its own slot. The plot still looks reasonable, so nothing tells you the axis is wrong. With age read as numbers, the engine also refuses the population pyramid’s sentence in Many groups, because it sorts the bands with order(), and order() needs a categorical axis. When age is read as text, it still needs its declared order. Without the declaration, order() sorts the bands alphabetically, one character at a time. The band 5 is then drawn between 45 and 50.

Each call above names one column, and a text argument can name more than one. gm_eras holds the same values in two columns: year as a number, era as a label. The calls above name only era, so year stays a number. To read the year as a label too, name both columns in one text argument:

  • R
  • Python
  • Julia
  • JavaScript
gm_eras <- gog_table("gm_eras", text = c("year", "era"))
gm_eras = gog_table("gm_eras", text=("year", "era"))
gm_eras = gog_table("gm_eras", text = ["year", "era"])
const gm_eras = await gog_table("gm_eras", ["year", "era"]);

Each language writes more than one name in its own way. R puts them inside c(), Python inside parentheses, and Julia and JavaScript inside square brackets. In Python, one name can also be written alone, as in text="age". Inside parentheses it needs a trailing comma, as in ("age",), and two names do not. In Julia and JavaScript, the second name is added inside the brackets, after a comma.

Only census, sessions, candles, gm_eras, gm_twelve_ends, ohio_turnout, eras, gm_four, thermal_moments and storm_seasons need a text argument; no other shared table does.

6.2.3 A date

The third thing a CSV cannot record is which columns are dates. Six tables have a column of dates: day in four of them (six_weeks, revenue, sessions and candles), at in monitoring, and week in quakes_2011. gog_table() returns each of these columns as text, so the axis gets one slot per date instead of a calendar axis. After reading, convert the column to your language’s date or timestamp type. In R, that is as.Date() for six_weeks, revenue, sessions, candles and quakes_2011. monitoring also records the hour, so it takes as.POSIXct(). In JavaScript, write a time after each date, so that it is midnight in local time: six_weeks.day.map((d) => new Date(d + "T00:00")). For monitoring, which has a time already, replace the space with a T: new Date(t.replace(" ", "T")). The JavaScript chapter explains why. Scales shows the calendar axis you get.

Some tables hold real data and some were made for this book. The tables whose names begin with gapminder or gm hold figures from the Gapminder Foundation, which released them into the public domain. So do asia_2007, recent, three_continents and two_readings. continents_2007, continent_means, life_ranges and world_median are computed from those figures. population_spikes, filled, eras and enclave join them to world_borders, the country outlines described below. iris_flowers, iris_measurements, iris_predicted, petals, petal_stars, maunga_whau, peak, band, relief, nyc_horizon, quakes_fiji and titanic are reshaped from tables included with R, and carry R’s own license. nightingale is Florence Nightingale’s table of the British army’s deaths in the Crimean War, 1854 to 1856. It comes from the HistData package, under the same license as R’s tables. lung_survival and lung_at_risk come from R’s survival package, under that package’s own license. world_borders is Natural Earth’s public-domain outline of the countries. cyclones and storm_seasons are US government records: the National Oceanic and Atmospheric Administration’s storms of hurricane strength, 1980 to 2025, as tracks and as counts. So are quakes_2011, us_counties and ohio_turnout: the US Geological Survey’s earthquakes of magnitude 5 or more in 2011, the Census Bureau’s counties of the 48 states between Canada and Mexico, with their poverty rates in 2023, and the share of each Ohio county’s citizens who voted in 2016, 2020 and 2024, from the Election Assistance Commission and the Census Bureau. Everything else was made for this book, each table to show one thing; census is two plausible city profiles, not a real census. The terms for each are in data/LICENSE.md.

6.4 What comes next

A table holds the rows, and says nothing about how they look on the page. Choosing a mark shows how to pick the mark that draws them. There are fourteen, and your question and your columns decide which one fits.
