30  Flow

Where did each part of a total go? Some tables record movement: each row says that some amount started in one place and finished in another. A flow diagram draws that movement. The places are grouped into stages, and the stages are drawn side by side. Bands carry each amount from stage to stage. The thicker the band, the larger the amount it carries. This picture is an alluvial diagram, one kind of Sankey diagram. The section Links in layers shows a Sankey diagram drawn from a table of links, and Where the limits are says what gog does not draw. No atom spells either name, just as there is no pie() atom.

gog builds that picture out of the table’s own columns. A stage is one of the table’s categorical columns. Its distinct values are the possible places at that stage, and each row sits in one of them. The flow transform computes the whole diagram from one table of such columns. This chapter uses the passengers and crew of the Titanic, the ship that sank in 1912. titanic holds one row per group of people. Four columns describe each group: class, sex, age (child or adult) and survived. A fifth, n, counts the people in that group. The table has one row for every combination of those four columns, so some rows count zero people:

titanic: first 5 of 32 rows
class sex age survived n
1st Male Child No 0
2nd Male Child No 0
3rd Male Child No 35
Crew Male Child No 0
1st Female Child No 0

30.1 The finished diagram

Who survived the sinking, and did class and sex change their chance of survival? The diagram below answers both:

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + y(n) +
  ribbon * flow(class, sex, survived) + color(survived) +
  zone * flow(class, sex, survived) +
  text * flow(class, sex, survived) + label(name) +
  title("Who survived, by class and sex")
(data(titanic) + y(col.n) +
  ribbon * flow(col["class"], col.sex, col.survived) + color(col.survived) +
  zone * flow(col["class"], col.sex, col.survived) +
  text * flow(col["class"], col.sex, col.survived) + label(col.name) +
  title("Who survived, by class and sex"))
data(titanic) + y(:n) + ribbon * flow(:class, :sex, :survived) +
  color(:survived) + zone * flow(:class, :sex, :survived) +
  text * flow(:class, :sex, :survived) + label(:name) +
  title("Who survived, by class and sex")
plot(data(titanic), y(col.n),
  layer(ribbon, flow(col.class, col.sex, col.survived)),
  color(col.survived),
  layer(zone, flow(col.class, col.sex, col.survived)),
  layer(text, flow(col.class, col.sex, col.survived)), label(col.name),
  title("Who survived, by class and sex"))

“Given titanic: y is n, ribbons derived by flow through class, sex and survived, colored by survived, and also zones derived by flow through class, sex and survived, and text derived by flow through class, sex and survived, label by name.”

Read it from left to right. Each white rectangle marks a slot: the part of a stage that one place takes, such as a class, a sex or an outcome. Each band is a group of people who share a class, a sex and an outcome, and its color is the outcome: blue for the people who survived, orange for the people who did not. The blue bands that leave the Female slot are much thicker than the orange ones, because 344 of the 470 women and girls survived. At the Male slot the orange bands are thicker, because only 367 of the 1,731 men and boys survived. Class mattered too. 203 of the 325 people in first class survived, compared with 178 of the 706 in third class.

30.2 Three layers

The sentence above has three layers. In each one, * joins the same transform, flow(...), to a different mark, and each mark draws one part of the picture:

Layer What it draws
ribbon * flow(...) the bands, which carry the counts from stage to stage
zone * flow(...) the slots, one rectangle for each place at each stage
text * flow(...) + label(name) the names, one inside each slot

The three layers compute the same positions from the same stages. So the bands end at the edges of the slots, and each name sits inside its slot. The next three sections add the layers one at a time, in the order of the table. They use two stages, class and survived, and Adding a stage then adds sex between them.

30.3 The bands

To build the diagram, start with the bands alone. Class is one stage and the outcome is another. Name the stages inside flow(), from left to right, and bind the count to y:

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + ribbon * flow(class, survived) + y(n) +
  title("Who survived, by class")
(data(titanic) + ribbon * flow(col["class"], col.survived) + y(col.n) +
  title("Who survived, by class"))
data(titanic) + ribbon * flow(:class, :survived) + y(:n) +
  title("Who survived, by class")
plot(data(titanic), layer(ribbon, flow(col.class, col.survived)),
  y(col.n), title("Who survived, by class"))

“Given titanic: ribbons derived by flow through class and survived, y is n.”

Each band is one path: one place at each stage, here a class and then an outcome. This plot does not outline the slots or name them, so find a path by its position. Inside each stage the slots stack from the bottom, in the order the column declares: 1st to Crew, and Yes before No. So the lowest band leaves the 1st slot and arrives at the Yes slot. It carries the 203 first-class passengers who survived, and it keeps that thickness at both ends. Rows that share a path become one band: their counts are added, and the band carries the total. The four 1st rows that end in Yes differ only in sex and age, and the atom names neither, so the four become one band.

flow() also sets both axes. With the count on y, the stages are drawn along the horizontal axis, each named by its column, in the order you name them inside flow(). The vertical axis is a continuous axis for the count. The bands at each stage stack from zero with no gaps. So the top edge of any band is the total of that band and every band below it.

The count is optional. Bind nothing and every row counts as 1, and the diagram counts rows instead of summing a column. partition uses that default too, and count tallies rows the same way. This table needs y(n): it holds one row per combination, so counting its rows would count combinations rather than people.

30.4 The slots

In the plot above, the bands that leave one place touch the bands that leave the next, so you cannot see where one place ends and the next begins. A zone layer draws the slots. Add zone * flow(class, survived), with the same stages as the bands. Both layers now use the count, so write y(n) before any mark, where it belongs to the plot and every layer reads it (Encoding scope):

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + y(n) +
  ribbon * flow(class, survived) +
  zone * flow(class, survived) +
  title("The same flow, with its slots")
(data(titanic) + y(col.n) +
  ribbon * flow(col["class"], col.survived) +
  zone * flow(col["class"], col.survived) +
  title("The same flow, with its slots"))
data(titanic) + y(:n) + ribbon * flow(:class, :survived) +
  zone * flow(:class, :survived) + title("The same flow, with its slots")
plot(data(titanic), y(col.n),
  layer(ribbon, flow(col.class, col.survived)),
  layer(zone, flow(col.class, col.survived)),
  title("The same flow, with its slots"))

“Given titanic: y is n, ribbons derived by flow through class and survived, and also zones derived by flow through class and survived.”

Each rectangle marks one slot. It covers the same part of the count axis as the bands that leave it or arrive at it, so each slot is as tall as the number of people at that place. A categorical axis also gives each category a slot, but there every slot is the same size. The top slot of the class stage is the crew, the largest group, with 885 people. At the outcome stage the larger slot is No: 1,490 of the 2,201 people did not survive.

Each slot is white with a thin black line around it, so only the bands have color and the edge of every slot is visible. Those are the defaults, and Choosing the colors shows how to change them. The slots still have no names, so you still count from the bottom to find each slot.

30.5 The names

A text layer names the slots. The transform writes each slot’s name into a column called name, exactly as partition does. Add a third layer, text * flow(class, survived), with the same stages again, and bind label(name) to draw that column:

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + y(n) +
  ribbon * flow(class, survived) +
  zone * flow(class, survived) +
  text * flow(class, survived) + label(name) +
  title("The same flow, with its slots named")
(data(titanic) + y(col.n) +
  ribbon * flow(col["class"], col.survived) +
  zone * flow(col["class"], col.survived) +
  text * flow(col["class"], col.survived) + label(col.name) +
  title("The same flow, with its slots named"))
data(titanic) + y(:n) + ribbon * flow(:class, :survived) +
  zone * flow(:class, :survived) + text * flow(:class, :survived) +
  label(:name) + title("The same flow, with its slots named")
plot(data(titanic), y(col.n),
  layer(ribbon, flow(col.class, col.survived)),
  layer(zone, flow(col.class, col.survived)),
  layer(text, flow(col.class, col.survived)), label(col.name),
  title("The same flow, with its slots named"))

“Given titanic: y is n, ribbons derived by flow through class and survived, and also zones derived by flow through class and survived, and text derived by flow through class and survived, label by name.”

Each name is drawn at the center of its slot. The layers are drawn in the order they are written, so the text layer comes last. If the text layer came before the zone layer, the white slots would hide the names.

The 1st slot is now easy to find, and the thicker of its two bands arrives at Yes. It carries the 203 of the 325 people in first class who survived, the number given under the finished diagram. Every later plot in this chapter keeps the three layers.

30.6 Adding a stage

The finished diagram has a third stage, sex, between class and the outcome. Add it by naming one more column inside flow(), in all three layers. Each path now passes through three stages, and each band is as thick as its count at every one:

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + y(n) +
  ribbon * flow(class, sex, survived) +
  zone * flow(class, sex, survived) +
  text * flow(class, sex, survived) + label(name) +
  title("Class, then sex, then survival")
(data(titanic) + y(col.n) +
  ribbon * flow(col["class"], col.sex, col.survived) +
  zone * flow(col["class"], col.sex, col.survived) +
  text * flow(col["class"], col.sex, col.survived) + label(col.name) +
  title("Class, then sex, then survival"))
data(titanic) + y(:n) + ribbon * flow(:class, :sex, :survived) +
  zone * flow(:class, :sex, :survived) +
  text * flow(:class, :sex, :survived) + label(:name) +
  title("Class, then sex, then survival")
plot(data(titanic), y(col.n),
  layer(ribbon, flow(col.class, col.sex, col.survived)),
  layer(zone, flow(col.class, col.sex, col.survived)),
  layer(text, flow(col.class, col.sex, col.survived)), label(col.name),
  title("Class, then sex, then survival"))

Each band is now a group of people with one class, one sex and one outcome. sex declares no order, so its slots follow the order its values first appear in the table: Male at the bottom, then Female. The band from 1st through Female to Yes carries 141 people, the women and girls in first class who survived. Most people in the Female slot arrive at Yes, and most in the Male slot arrive at No, as in the finished diagram.

30.7 Color from a stage

With three stages the bands cross one another, and when every band has the same color, one band is hard to follow through a crossing. A band runs through every stage, so any stage can color it. The finished diagram at the start of this chapter colors each band by survived, the slot it arrives at. Coloring by class gives each band the color of the slot it leaves at the first stage instead:

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + y(n) +
  ribbon * flow(class, sex, survived) + color(class) +
  zone * flow(class, sex, survived) +
  text * flow(class, sex, survived) + label(name) +
  title("The same paths, colored by class")
(data(titanic) + y(col.n) +
  ribbon * flow(col["class"], col.sex, col.survived) + color(col["class"]) +
  zone * flow(col["class"], col.sex, col.survived) +
  text * flow(col["class"], col.sex, col.survived) + label(col.name) +
  title("The same paths, colored by class"))
data(titanic) + y(:n) + ribbon * flow(:class, :sex, :survived) +
  color(:class) + zone * flow(:class, :sex, :survived) +
  text * flow(:class, :sex, :survived) + label(:name) +
  title("The same paths, colored by class")
plot(data(titanic), y(col.n),
  layer(ribbon, flow(col.class, col.sex, col.survived)), color(col.class),
  layer(zone, flow(col.class, col.sex, col.survived)),
  layer(text, flow(col.class, col.sex, col.survived)), label(col.name),
  title("The same paths, colored by class"))

Now you can see which classes arrive in each later slot. Coloring by survived and coloring by class answer two questions: who lived, and where each class went.

color() is written after the ribbon layer, so it belongs to the bands alone. Written before the marks, it would reach the slots and the names as well. gog refuses that, because a slot and its name take their color from style().

30.8 Color from another column

Did the women in third class survive as often as the women in first class? A color can show it inside each band, with no third stage. Any categorical column can color the bands, not only a stage. A column that is not a stage splits each band into one part for each of its values. A categorical color splits a line the same way, into one line for each category. The parts of one band lie next to each other across its thickness and follow its path, and the slots are the same as without the color. With survived as a color instead of a stage, a flow through class and sex shows who survived in every band:

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + y(n) +
  ribbon * flow(class, sex) + color(survived) +
  zone * flow(class, sex) +
  text * flow(class, sex) + label(name) +
  title("Class, then sex, colored by survival")
(data(titanic) + y(col.n) +
  ribbon * flow(col["class"], col.sex) + color(col.survived) +
  zone * flow(col["class"], col.sex) +
  text * flow(col["class"], col.sex) + label(col.name) +
  title("Class, then sex, colored by survival"))
data(titanic) + y(:n) + ribbon * flow(:class, :sex) + color(:survived) +
  zone * flow(:class, :sex) + text * flow(:class, :sex) + label(:name) +
  title("Class, then sex, colored by survival")
plot(data(titanic), y(col.n), layer(ribbon, flow(col.class, col.sex)),
  color(col.survived), layer(zone, flow(col.class, col.sex)),
  layer(text, flow(col.class, col.sex)), label(col.name),
  title("Class, then sex, colored by survival"))

“Given titanic: y is n, ribbons derived by flow through class and sex, colored by survived, and also zones derived by flow through class and sex, and text derived by flow through class and sex, label by name.”

Each band from a class to a sex now has a blue part for the people who survived and an orange part for the people who did not. The band from 1st to Female is nearly all blue: 141 of its 145 people survived. The band from 3rd to Female is less than half blue: 90 of 196. The finished diagram shows the same split with survived as a stage, where the outcome also gets slots of its own. As a color, the outcome needs no slots of its own, and the legend names its values.

Only a categorical column can split a band, because its values are groups. A continuous column is refused, as it is on every ribbon.

30.9 Choosing the colors

Every color in this chapter so far is a default. The bands take gog’s default palette and are translucent, the slots are white with a thin black line around them, and the names are near-black. You choose each one in its own layer.

The bands take their colors from a column, and palette() chooses the color for each value of that column. Write each value beside the color you want, as Colors by name explains. Name every value, since gog refuses a palette that leaves one out:

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + y(n) +
  ribbon * flow(class, sex, survived) + color(survived) +
  palette(c(Yes = "steelblue", No = "darkgray")) +
  zone * flow(class, sex, survived) +
  text * flow(class, sex, survived) + label(name) +
  title("The survivors in blue")
(data(titanic) + y(col.n) +
  ribbon * flow(col["class"], col.sex, col.survived) + color(col.survived) +
  palette({"Yes": "steelblue", "No": "darkgray"}) +
  zone * flow(col["class"], col.sex, col.survived) +
  text * flow(col["class"], col.sex, col.survived) + label(col.name) +
  title("The survivors in blue"))
data(titanic) + y(:n) + ribbon * flow(:class, :sex, :survived) +
  color(:survived) + palette(["Yes" => "steelblue", "No" => "darkgray"]) +
  zone * flow(:class, :sex, :survived) +
  text * flow(:class, :sex, :survived) + label(:name) +
  title("The survivors in blue")
plot(data(titanic), y(col.n),
  layer(ribbon, flow(col.class, col.sex, col.survived)),
  color(col.survived), palette({ Yes: "steelblue", No: "darkgray" }),
  layer(zone, flow(col.class, col.sex, col.survived)),
  layer(text, flow(col.class, col.sex, col.survived)), label(col.name),
  title("The survivors in blue"))

“Given titanic: y is n, ribbons derived by flow through class, sex and survived, colored by survived, with a palette naming Yes steelblue and No darkgray, and also zones derived by flow through class, sex and survived, and text derived by flow through class, sex and survived, label by name.”

The bands of the survivors are blue and the others are gray, so the survivors are easy to find. A band is translucent, so it looks lighter than the color you name, and two bands that cross both stay visible. To give every band the same color, leave out color() and write style(color = ) after the ribbon layer. style(opacity = ) there sets how translucent the bands are, with or without color().

A slot sits at one stage, so no single column can color every slot, and the same is true of the names. The zone and text layers take their settings from style() instead, one value for each layer. On the zone layer, color fills the slots, and border_color and border_size draw the line around each one. On the text layer, color and size set the color and the size of the names:

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + y(n) +
  ribbon * flow(class, sex, survived) + color(survived) +
  palette(c(Yes = "steelblue", No = "darkgray")) +
  zone * flow(class, sex, survived) +
  style(color = "midnightblue", border_color = "white", border_size = 2) +
  text * flow(class, sex, survived) + label(name) +
  style(color = "white", size = 14) +
  title("Dark slots with white names")
(data(titanic) + y(col.n) +
  ribbon * flow(col["class"], col.sex, col.survived) + color(col.survived) +
  palette({"Yes": "steelblue", "No": "darkgray"}) +
  zone * flow(col["class"], col.sex, col.survived) +
  style(color = "midnightblue", border_color = "white", border_size = 2) +
  text * flow(col["class"], col.sex, col.survived) + label(col.name) +
  style(color = "white", size = 14) +
  title("Dark slots with white names"))
data(titanic) + y(:n) + ribbon * flow(:class, :sex, :survived) +
  color(:survived) + palette(["Yes" => "steelblue", "No" => "darkgray"]) +
  zone * flow(:class, :sex, :survived) +
  style(color = "midnightblue", border_color = "white", border_size = 2) +
  text * flow(:class, :sex, :survived) + label(:name) +
  style(color = "white", size = 14) + title("Dark slots with white names")
plot(data(titanic), y(col.n),
  layer(ribbon, flow(col.class, col.sex, col.survived)),
  color(col.survived), palette({ Yes: "steelblue", No: "darkgray" }),
  layer(zone, flow(col.class, col.sex, col.survived)),
  style({ color: "midnightblue", border_color: "white", border_size: 2 }),
  layer(text, flow(col.class, col.sex, col.survived)), label(col.name),
  style({ color: "white", size: 14 }),
  title("Dark slots with white names"))

“Given titanic: y is n, ribbons derived by flow through class, sex and survived, colored by survived, with a palette naming Yes steelblue and No darkgray, and also zones derived by flow through class, sex and survived, colored midnightblue, with border color white and border size 2, and text derived by flow through class, sex and survived, label by name, colored white, with size 14.”

Each style() is written after the mark it changes, so it changes that layer and no other. On the dark fill, the white line shows where each slot ends, and border_size = 0 would remove it. The zone layer also takes opacity, as every mark does, and pattern, as the five filled regions do (Style).

30.10 Room for long names

In a flow that runs left to right the slots are tall and narrow. The names in titanic are short, so every one fits. A longer name, such as Member of the crew, would be wider than its slot, and gog would draw it across the slot’s edges, over the bands. There are two ways to give it more space.

The first turns the names. style(angle = 90) on the text layer turns every name upward, so it runs along its slot, as Turning a label explains:

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + y(n) +
  ribbon * flow(class, sex, survived) + color(survived) +
  zone * flow(class, sex, survived) +
  text * flow(class, sex, survived) + label(name) + style(angle = 90) +
  title("Names turned 90 degrees")
(data(titanic) + y(col.n) +
  ribbon * flow(col["class"], col.sex, col.survived) + color(col.survived) +
  zone * flow(col["class"], col.sex, col.survived) +
  text * flow(col["class"], col.sex, col.survived) + label(col.name) + style(angle = 90) +
  title("Names turned 90 degrees"))
data(titanic) + y(:n) + ribbon * flow(:class, :sex, :survived) +
  color(:survived) + zone * flow(:class, :sex, :survived) +
  text * flow(:class, :sex, :survived) + label(:name) +
  style(angle = 90) + title("Names turned 90 degrees")
plot(data(titanic), y(col.n),
  layer(ribbon, flow(col.class, col.sex, col.survived)),
  color(col.survived),
  layer(zone, flow(col.class, col.sex, col.survived)),
  layer(text, flow(col.class, col.sex, col.survived)), label(col.name),
  style({ angle: 90 }), title("Names turned 90 degrees"))

“Given titanic: y is n, ribbons derived by flow through class, sex and survived, colored by survived, and also zones derived by flow through class, sex and survived, and text derived by flow through class, sex and survived, label by name, with angle 90.”

Each name is now written upward, so it must fit the slot’s height, not the slot’s width.

The second places the stages from top to bottom. Bind the count to x instead of y, and the first stage is at the top of the plot. Each slot is then wide and short, so a long name fits across it unless the slot’s count is small. The sentence is the finished diagram’s, with x(n) in place of y(n) and a new title. gog takes the direction from the axis that holds the count, as it does for a bar chart (Horizontal bars):

  • R
  • Python
  • Julia
  • JavaScript
data(titanic) + x(n) +
  ribbon * flow(class, sex, survived) + color(survived) +
  zone * flow(class, sex, survived) +
  text * flow(class, sex, survived) + label(name) +
  title("The same flow, from top to bottom")
(data(titanic) + x(col.n) +
  ribbon * flow(col["class"], col.sex, col.survived) + color(col.survived) +
  zone * flow(col["class"], col.sex, col.survived) +
  text * flow(col["class"], col.sex, col.survived) + label(col.name) +
  title("The same flow, from top to bottom"))

30.13 Two columns that name the same places

30.16 Links in layers

Some tables record movement whose paths do not all pass through the same stages. budget holds one household’s money for a month. Two incomes are added into one, Income. From there the money goes to Taxes, Savings and four groups of spending, and each group divides again. Each row is one link, an amount that moves from one place to the next:

budget: first 5 of 22 rows
source target amount
Salary Income 3400
Side work Income 600
Income Taxes 900
Income Housing 1275
Income Food 605

Taxes and Savings are one step after Income, and no band leaves them. Rent is one step later, and no band leaves it either. Utilities, at the same step as Rent, divides again into Energy and Water. Stage columns cannot hold that, because every row would need a value at every stage. layered = TRUE says that each row is a link between two places. gog then puts the places in layers. A layer is drawn like a stage, but gog computes it from the links instead of reading a column. It is a different thing from a layer of the sentence, such as the ribbon layer:

This picture is a Sankey diagram. Each place stands in the first layer that comes after every place that sends to it. Salary and Side work send to Income, so Income stands in the second layer. Taxes stands in the third layer, and no band leaves it. Energy stands in the fifth layer, after Housing in the third and Utilities in the fourth. Each slot is as tall as the larger of what arrives at the place and what leaves it. A small gap separates the places of one layer. color(source) gives each band the color of the place it leaves.

gog also computes the order of the places in each layer. It puts each place near the places it links to, so that few bands cross. The slots are too narrow to hold a name, so each name stands beside its slot. In every layer but the last, it stands to the right, on top of any bands that leave the place. In the last layer it stands to the left. Like the shared flow, a layered flow writes no numbers on its axes. Its layers have no names to write along one axis. Along the other, the gaps between places take space too, so the edge of a slot is not a running total there.

  layer(zone, flow(col.source, col.target, { layered: true })),
  layer(text, flow(col.source, col.target, { layered: true })),
  label(col.name), brush(col.name, { at: "Housing" }),
  title("What arrives at Housing and what leaves it"))

The bands from Utilities to Energy and Water stay dimmed, although here all of their money passed through Housing. A place can receive money from several places, as Income does. A band that leaves such a place carries some of each, and the picture cannot show how much. So a selection keeps only the bands that arrive at the place or leave it, whatever the table holds. In the web edition, a click on a slot selects that place, as on the other flows.

30.19 Where the limits are

The two limits below are not mistakes in your sentence. Each is valid grammar that this engine does not draw.

A flow with stages is valid grammar in polar() too. Each stage would get a ring of its own, so the picture would be a circular alluvial diagram, not the chord diagram above. This engine does not draw it, and the message points to shared = TRUE for two columns that name one set of places:

A layered flow has a limit too. Its bands may skip a layer, or stop before the last layer, but its links may not form a cycle. Links that form a cycle have no layers, because no place in the cycle comes first. Some tools draw a cycle as a band that runs back across the diagram. The message points to shared = TRUE instead, which puts every place on one axis and draws the same links as arcs.

30.20 Choosing a flow diagram

This chapter has drawn four kinds of flow diagram: alluvial, Sankey, arc and chord. To choose one, start from what one row of your table says. The last row of the table is a fifth choice, the network diagram:

What one row says A question it answers The diagram
a group and its place at each of several stages, as in titanic How did each group move from stage to stage? an alluvial diagram (The finished diagram)
a link, an amount that moves from one place to the next, with no cycles, as in budget Where does the total go, step by step? a Sankey diagram (Links in layers)
an amount between two places of one kind, often in both directions, as in trade_partners Who sends to whom, and how much each way? an arc diagram, or the same links on a ring, a chord diagram (Two columns that name the same places)
a connection between two places, when who is connected matters more than how much What is connected to what? a network diagram (Network)

A flow diagram shows the pattern of the movement, but a band is hard to compare with a band in another part of the picture. A tile plot gives each pair of places its own cell, so every pair has a fixed place in a grid:

  • R
  • Python
  • Julia
  • JavaScript
data(trade_partners) + zone + x(importer) + y(exporter) + color(billions) +
  title("Trade between countries, one cell per pair")
(data(trade_partners) + zone + x(col.importer) + y(col.exporter) + color(col.billions) +
  title("Trade between countries, one cell per pair"))
data(trade_partners) + zone + x(:importer) + y(:exporter) +
  color(:billions) + title("Trade between countries, one cell per pair")
plot(data(trade_partners), zone, x(col.importer), y(col.exporter),
  color(col.billions),
  title("Trade between countries, one cell per pair"))

“Given trade partners: zones, x is importer, y is exporter, color by billions.”

Each row of cells is an exporter, and each column of cells is an importer. The darkest cell is China’s exports to the United States, the largest amount in the table. The cells for Mexico and Canada are nearly as dark, so the shades alone do not say which is larger. A reader compares lengths more accurately than shades of a color, so draw the amounts as bars when the comparison must be precise.

Four more suggestions help you draw a flow diagram. First, color the bands by the column that answers your question. On a flow with stages, the first stage shows where each group goes, and the last shows the outcomes. Second, add brush to select one place: the bands that meet it keep their colors, and the others are dimmed. With brush written, a click on a slot in the web edition selects another place. Third, use few places. Before you draw, give the small places one shared name in your table, such as Other. On a layered flow, give it only to places that do not link to each other: a link from Other to Other is a cycle. Fourth, in an arc or a chord diagram, the order of the places decides how long the bands are and how often they cross. So declare an order that means something, such as by continent.

30.21 What comes next

A flow with stages stacks each stage’s slots in the order you declare, or else in the table’s order. Cluster computes an order from the data instead: it joins the categories that are most alike into a tree, and puts an axis in the tree’s order.
